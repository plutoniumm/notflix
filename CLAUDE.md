# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & Run

```sh
make run          # stop running server, rebuild, start DETACHED on :4242 (+ TV on :4444); logs → notflix.log
make fg           # same, but in the foreground
make stop         # SIGTERM + wait for :4242 to clear
make build        # build Go binary + both frontend bundles (no run)
pnpm run dev      # main frontend watch mode (Vite) — does NOT rebuild the TV bundle
go test ./...     # all Go tests
go test ./server/media/ -run TestLadderFor_NeverEmpty   # single test
go test ./server/media/ -short              # skip ffmpeg e2e tests
node --test tools/*.test.ts                 # frontend tests (node strips types; no runner dep) — build first
```

`make run` is the canonical way to build and start. It stops the old server **before** building on purpose: `clean` unlinks `./notflix`, and a process started from an unlinked path keeps serving the old build off the deleted inode. Stop is SIGTERM, never KILL, so `library.Shutdown()` and `jobs.Aria2Stop()` get to run. The build injects `-ldflags "-X main.buildTime=..."`; don't invoke `go build` directly — you'll lose the buildTime stamp (surfaced at `/api/build` and compared against the frontend's `__BUILD_TIME__` for staleness).

Tests live beside their subjects in all three server packages. The ffmpeg-driven e2e tests (`server/media/dual_path_test.go`, `av1_grid_test.go`, clip/aspect/surround) skip cleanly under `testing.Short()` or when `libsvtav1` isn't in the local ffmpeg build. Tests that hit live services skip unless an env var opts in: `RECO_LIVE=1`, `BLURB_LIVE=<mp4>`, `TRANSLATE_LIVE=<vtt>`, `RETRANSLATE_LIVE=<vtt>`, `ANIM_LIVE="<mp4>:anime,<mp4>:live"`.

Frontend tests run on bare `node` (it strips the TypeScript itself). `parity.test.ts` fails if the README's key table drifts from `KEYS` in `src/player/ux.ts`. `fmt.test.ts` pins the edge cases the old per-component formatters got wrong — hour tiers, sub-MB byte tiers, NaN, negatives — including a `legacy` block asserting the *old wrong* outputs so the fix can't silently regress. `mobile.test.ts` asserts against the **compiled** bundle for rules that can't be exercised without a device: every hover-revealed control also reveals under `@media (hover: none)` (an `opacity: 0` button still takes taps), 44px touch targets, 16px fields (iOS zooms below that and never back), safe-area insets, `100dvh`.

## Architecture

**Go backend (Gin)** serves the API and the static frontend from `public/`. Three sub-packages, each owning a domain:

- `server/library/` — roots, file discovery, hash, cleanup, KV store, corrupt scan, pipeline ledger, stats, download history. Owns the `Library{Roots, Caps}` type (receiver for everything that used to take `roots []string`) and `FFRun`, the single ffmpeg invocation wrapper.
- `server/media/` — streaming + transcoding + cache: HLS, MP4 range serving, probe, conversion, repair, subtitles, thumbnails, trickplay sprites, skip detection, phase status.
- `server/jobs/` — background work: aria2 RPC, yt-dlp, torrent search, whisper subprocess, ollama translation (+ glossary, retranslate), blurbs, search embeddings, LLM organize (via saturn), Tailscale identity, shared `Pool` + `Tracker` primitives.
- `server/tv/` — the TV command bus (see **TV app** below).
- `server/x/` — leaf stdlib, imports nothing internal so even `library` can use it without a cycle. `x/atom` (atomic `WriteFile`/`SaveJSON`/`LoadJSON` — tmp + rename, and `LoadJSON` keeps "absent" distinct from "malformed"), `x/httpc` (one outbound client with an **enforced** timeout and a **mandatory** 2xx check; a zero timeout falls back to 30s, so "no deadline" is unreachable and "write an HTTP error page to disk" is unrepresentable).

`main.go` resolves the root set, wires cross-package callbacks, starts background goroutines, and declares the route table. Handlers live in `library/handlers.go`, `media/handlers.go`, and the domain files.

**Roots** are declared in `main.go` as `configuredRoots`. `~/…` entries are auto-created; bare absolute paths (`/Volumes/…`) must pre-exist — never auto-created, since a regular dir at a mountpoint silently shadows the volume. Every root failure is non-fatal: boot must survive an unmounted drive. `rootCaps` is a **UI-only** soft quota (cosmetic budgeting for roots sharing the boot disk); writes aren't enforced.

**Package dependencies**: `library` is standalone. `jobs` imports `library`. `media` imports both. Cycles are broken with function-pointer callbacks wired in `main.go`:
- `jobs.OnDownloads = media.ProcessAll` (aria2 → reprocess)
- `library.IsTorrentBusy = jobs.Aria2Owns` (busy gate — a single RLock'd lookup; `IsBusy` runs per file in every background pass, so the old whole-map copy was O(paths) per check)
- `library.IdentityFromIP` → `jobs.TailscaleIdentity`, with `library.Device` mirroring `jobs.Identity` field-for-field so `library` never imports `jobs`.

**Svelte 5 frontend** compiled by Vite into `public/assets/` as **two separate, unsplit builds**: `vite.config.ts` (`src/main.ts` → `notflix.js`/`.css`) and `vite.tv.config.ts` (`src/tv/main.ts` → `tv.js`/`.css`, targeting es2017/Safari 11/Chrome 61 for old TV browsers). Never merge them into one rollup with two entries: shared code gets hoisted into a hash-named chunk, which pulls video.js's CSS out of `notflix.css` and emits a filename the service worker's fixed precache list can't reference. Main app routing (`src/App.svelte`) is **path + query based**: `/manage` → Manage, `/history` → History, `?video=<rel>` → Player, else Home. The tree mirrors the backend:

- `src/core/` — the frontend stdlib. **Reach for these before hand-rolling.** `fmt.ts` is *every* number→string (`dur`/`durWords`/`bytes`/`rate`/`ago`/`pct`) — five drifted copies once disagreed, rendering a 2-hour job as "122m 5s" and a 400 KB/s download as "0 MB/s"; never write a formatter in a component. `store.ts` (`local(key, fallback)`) — `localStorage` *throws* when site data is blocked, so never call it directly. `path.ts` (`join(dir, name)`, which knows `dir === "."` is the root). `poll.ts` (`usePoll` — hidden-tab-aware; use instead of `setInterval`). `api.ts` (raw `GET/POST/DEL/POSTForm/head` + typed `api.*`; errors auto-toast unless `silent`). Plus `kv.ts`, `events.svelte.ts` (`PlayerState` + timing constants; re-exports `fmtTime`/`fmtAgo` from `fmt.ts`), `toast.svelte.ts` + `ToastHost.svelte`, `idb.ts`, `video.ts` (`clean`, `vidURL`, `thumbFail`).
- `src/components/` — shared presentational bits: `MediaCard.svelte` (the one video tile; owns the thumbnail fallback), `ScrollRow.svelte` (arrow chrome around a caller-supplied strip), `ProgressBar`, `Badge`, `EmptyState`, `Icon`, `BackLink`.
- `src/library/` — Home, Manage, Organize, rows (File/Folder/Show/Continues), Magnet, Downloads, `homeData.svelte.ts` (row grouping), `torrentName.ts` (season parsing), `dl.ts` (BackgroundFetch + IndexedDB).
- `src/player/` — Player + subcomponents (bar, dock, progress, volume, sync, tune, whisper, skip, related, Download), `subs.ts`, `ux.ts`, `avsync.ts`, `watch.ts`, `sprite.svelte.ts`, `view.svelte.ts` (`PlayerView` = `PlayerState + SubsManager + AudioManager`).
- `src/tv/` — the TV screen + phone remote; imports nothing from the main app.

**The default home surface is `Tonight.svelte`, not the catalogue.** A grid of everything has no end, so it can only be abandoned, never finished — it is a browsing surface by construction. `tonight.ts` instead returns at most 4 candidates, each carrying the reason it is there (`after S01E07`, `stopped 12d ago`, `not started`) and a stopping cue (`last episode`, `2 more after this`). It is deterministic: the same library state always produces the same list, because a shuffle is a variable reward. Home keeps the full grid behind `mode === "library"` (the `L` key, the sun button, or any search — searching *is* going looking), persisted in `local("home-mode")`. The stage is sized `100dvh - var(--hdr)` with the header measured via `bind:clientHeight`, and must never scroll.

Motion notes: `--ease-spring*` in `global.css` are real damped-spring responses sampled into `linear()` — a cubic-bezier can overshoot once but cannot oscillate, so the old cubic "spring" was a single lurch. `src/core/room.svelte.ts` drives the ambient page field on 1/f (Voss-McCartney, `noise.ts`) noise rather than a keyframe loop, and breathes it when the media pipeline is working; the Player doesn't mount it because it paints `--art-1`/`--art-2` from the frame itself. `prefers-reduced-motion` is deliberately not honoured anywhere — single-user system, see `research.md` for what each choice is grounded in.

## Key Patterns

**Every ffprobe goes through `library.Probes` — the UFO probe manager** (`server/library/ufo.go`). It single-flights *and* memoises, keyed on path + size + mtime. Opening one title used to fire four separate `ffprobe -show_streams` runs on the same file within ~100ms (HLSMaster, HLSAVOffset, AudioInfo, Subctx), plus a `-show_format` per playlist request; measured on a loaded box, `/api/audio/info` was 1345ms and `/api/subs/info` 737ms, repeatably, because nothing was shared and nothing was kept. Now 0.7ms. Failures are never cached (a transient failure under load must not be pinned for the process's life) and every probe carries a 60s deadline — most call sites previously passed `context.Background()` with none. Call `Probes.Forget(path)` after rewriting a file in place.

**`probePackets` runs for AV1 only** (`server/media/hls.go`). It reads the WHOLE file — 14s on a 2.2GB internal file, 43s on a 2.5GB one over the USB volume — and for h264 every consumer of what it produces (`kfTimes`, `bounds`, `segBitrates`, peak/avg) is gated behind `codec == av1` or `canCopyVideo`, which is hardcoded `false`. So on an h264 title it was a multi-gigabyte read that nothing read back. If h264 copy-passthrough is ever re-enabled, the gate must come back with it.

**`srcInfo` is persisted** to `cache/probe/<basename hash>.json` (`server/media/srcinfocache.go`), stamped with size + mtime + `hlsURLVer`. It was memory-only, so every restart re-paid the probe on the first open of every title: a cold `/api/hls/master` measured **31.9s**, now 0.27s cold and ~5ms after a restart. `kfTimes` is deliberately NOT persisted — it is only read to derive `bounds` (already stored) and by `canCopyAV1`, which looks at `len()` and `[0]`, so one float and a count reproduce both.

**`Nice` means `taskpolicy -c utility -d throttle`, not `nice -n 19`** (`server/library/ffmpeg.go`). The library lives on a **USB external SSD**, so the contended resource is that one IO queue — and Darwin exposes IO priority through a separate knob (`setiopolicy_np`/`IOPOL_THROTTLE`) that `nice` never touches. The most carefully niced encode was still starving playback at the disk; `-d throttle` is that IO tier. The CPU side is a `utility` clamp, **not** `-b`: background QoS pins work to the 4 E-cores even on an idle machine, which ran a 4K SVT-AV1 encode at 1 fps (~52h per film) with 12 P-cores asleep; `utility` measured 27 fps and still yields to anything interactive. Note `ps -o nice` reads 0 afterwards — a QoS clamp is not a nice value. Batch work uses `library.FFNice`; `library.FF` is for interactive paths only.

**Compat conversions stay on the media engine** (`videoArgs` in `server/media/convert.go`): with `h264_videotoolbox` the input gets `-hwaccel videotoolbox -hwaccel_output_format videotoolbox_vld` and no `-pix_fmt` (the High profile makes VT do the 10→8-bit itself) — 4K HEVC 12 → 54 fps, 50 dB PSNR vs the CPU path. VT-undecodable sources (Hi10P, MPEG-4 ASP) fall back to software on their own. **Rotated sources stay on the CPU path**: hardware frames skip ffmpeg's autorotate and a portrait clip came out sideways with its rotation tag dropped (`TestCompatRotatedStaysOnCPU`). Hardware decode was measured for the AV1 path too and bought ~6% — the SVT encoder is the cost there, so it was left out.

**Unrecoverable files carry a `dead:<basename hash>` mark** (`server/library/corrupt.go`), stamped with size+mtime so replaced bytes re-qualify. Without it, 366 permanently-dead files (physically megabytes of zeros) were re-probed by `ScanCorrupt` 8-wide and re-attempted by `RepairAll` — 732 ffmpeg spawns, one a full AV1 re-encode with a 60-minute timeout — on every sweep and every restart. `ScanCorrupt` still puts them in the corrupt set without probing: dropping them would let convert and thumbs treat them as healthy.

**Upscaler** (`src/player/upscale.ts` + `server/media/animation.go`): a WebGL2 overlay that runs per frame. Four modes, exported as `MODES`: the hand-written analytic FSR 1.0 (EASU + RCAS), **FSRCNNX** and **NNEDI3** (trained live-action networks, vendored in `src/player/livenets/`), and a 17-pass Anime4K convnet for animation. WebGL2, not WebGPU, because the shaders are GLSL already and WebGL2 is available everywhere this runs.

**The mode IS a user setting** — a single user A/B-tests by eye, so the top bar shows one button per algorithm (`Auto · FSR · CNNX · NNEDI · A4K`; clicking the lit one turns it off), persisted as `local("upscale-mode")` (`Pick` = a mode, `"auto"` or `"off"`; seeded once from the old `upscale-on` boolean). **Auto** is decided at pipeline time by the `anim` phase, which hands five evenly-spaced sprite-sheet tiles to the vision model and stores `anim:<basename hash>` in KV like `codec:`/`skip:`/`poster:` — measured 6/6 correct on City Hunter, Millennium Actress, The Roundup, The Outlaws and Wedding Crashers at ~5.6s per title. Marked → Anime4K, absent mark → FSRCNNX (the best measured live-action mode). Chained after `posters` because both read the sprite sheet and share the 1-wide vision gate.

The anime path is a real convnet: Anime4K's `Restore_CNN_M` (8 passes) then `Upscale_CNN_x2_M` (9 passes), vendored unmodified under `src/player/anime4k/` and run by `mpvshader.ts`, which parses mpv's `//!HOOK` dialect into WebGL2 passes. The weights ARE the shader — tens of thousands of inline `mat4` literals — so nothing is downloaded at runtime and upstream can be re-pulled by overwriting the file. Measured on pinned frames at 2560x1440: **+71% to +94% detail on anime**, against +8% to +18% for the analytic FSR on live action (which scales with upscale factor). 100% realtime playback, 0–1 dropped frames, at both 1440p and 4K.

**Live-action networks hook LUMA** (they see brightness only; mpv merges colour back), so `Chain` takes a `Luma` argument: a split pass derives Rec.709 Y' from the frame, the network runs on it, and a merge adds the network's brightness detail onto a bilinear upscale of the colour frame (the same delta on R, G and B moves Y' and leaves Cb/Cr alone). `//!OFFSET` is accumulated and corrected in the merge (NNEDI3 shifts half a texel per axis), and `HOOKED.w`/`.h` in size directives resolve to the hooked texture. FSRCNNX was once vendored and removed as "−3%, a no-op" — that measurement was a runtime bug (LUMA was silently the red channel; with `HOOKED` sizes resolving to 0, NNEDI3 rendered into a 1px strip). Measured 2026-11-12 on six 4K live-action frames halved and upscaled back, through the real `Upscaler`: **FSRCNNX +0.59 dB over FSR** (ahead on 5/6), NNEDI3 level with FSR, Anime4K −5.2 dB on live action. Full numbers in `livenets/README.md`. **Measure with untagged pixels**: ffmpeg-extracted PNGs carry cICP/gAMA tags and a browser colour-converts them on upload unless `UNPACK_COLORSPACE_CONVERSION_WEBGL` is `NONE` (or `createImageBitmap(…, {colorSpaceConversion: "none"})`) — the first run of that benchmark was darkened by exactly this and scored every method within 0.1 dB. GAN-class models (Real-ESRGAN compact, SPAN) were measured too and are not realtime: 2.7–9 s per 1080p frame through ONNX Runtime Web on WebGPU, and 0.4–1.2M multiply-adds per pixel put them 5–10× over a 24 fps budget even with a perfect runtime; the only realtime-sized ones published (SuperUltraCompact) are anime-trained.

Five things in that runtime look like bugs and are not, each of which cost a debugging round:

- **Intermediate passes must render to float textures** (`RGBA16F`). Convolution activations are signed; in a UNORM target everything negative clamps to zero and the network silently outputs mush. No float render target = fall back to the analytic shader rather than render something subtly wrong.
- **`#target()` selects a scratch texture unit before creating a texture.** Creating one binds it to the *active* unit, so allocating a render target while an input unit was selected left the output bound as a sampler — a feedback loop, which WebGL answers with `INVALID_OPERATION` on every single draw.
- **The texture remap is deferred until after the draw.** Both chains end with a pass that BINDs `MAIN` and SAVEs `MAIN`; it has to read the old texture while writing a new one, so the name is repointed only once the pass is done.
- **Null uniform locations are checked.** A bind a pass never samples is optimised out, and `gl.uniform1i(null, …)` is not a no-op — it raises `INVALID_OPERATION` and poisons the rest of the frame.
- **Accessors are MACROS, not functions.** mpv defines `texOff` as a macro wrapping `vec2(off)`, so shaders legitimately call it with a scalar. A `vec4 f(vec2)` overload rejects that, and GLSL ES has no implicit scalar-to-vector conversion.
- **The Y flip happens once, at texture upload** (`UNPACK_FLIP_Y_WEBGL`), never per pass. Flipping in the vertex shader flips the INTERMEDIATE targets too, so a derived texture comes back inverted relative to the frame it was derived from. The output still looks coherent, just upside down — which is exactly the kind of bug that survives a "does it render?" check, and it silently invalidated a round of measurements before it was caught.

Two more that apply to both modes: `preserveDrawingBuffer: true` is **mandatory** — `requestVideoFrameCallback` only fires when a new frame is presented, so the loop stops dead on pause, and without it the buffer is cleared after compositing and the canvas goes black exactly when the viewer is staring at a still frame. And the pass is **desktop-only** (`supported()` rejects `(hover: none)`): the shader is nothing, but routing video through a canvas gives up the hardware overlay path, so the GPU wakes per frame — battery cost on the device most likely to be on cellular. The `<video>` stays the element that owns audio, PiP and fullscreen; it is only made transparent.

**gzip is an ALLOWLIST of paths, never a content-type sniff** (`server/x/gz`). Hand-rolled, no dependency. Three things must never be compressed and a sniff gets all three wrong: `/video` and `/subs` serve HTTP 206 Range responses (compressing a byte range makes the offsets lie); segments, inits, images and clips are already-compressed media (deflating them spends the scarce resource, CPU, to grow the payload); and `/api/subs/whisper/stream` is SSE, which `gzip.Writer` would buffer until Close. Measured: `notflix.js` 933KB → 343KB, an h264 playlist 282KB → 5.7KB.

**Every ffmpeg call goes through `library.FFRun`** (`server/library/ffmpeg.go`). It prepends `-nostdin -v error`, routes `-progress` to its own stdout pipe (keeping progress out of the error buffer), caps retained stderr at 8 KB, supports `Nice` (batch work must never starve live streaming), and derives from a package-level `shutdownCtx`. `library.Shutdown()` cancels every in-flight ffmpeg on SIGTERM/SIGINT — orphaned encoders from a past run kept writing files the next run then stomped. Same reason `jobs.Aria2Stop()` runs on shutdown: an orphaned aria2c squats :6800 and wedges every later spawn.

**`library.IsBusy(path)` is the single "hands off, come back later" gate** for all background work (convert, thumbs, sprite, corrupt scan, clean). It's true when aria2 owns the file, a control sidecar exists (`.aria2`, `.tmp`, `.audio.tmp`), or the file was modified in the last 30s. If you're adding a background pass, gate it on `IsBusy`.

**The KV store has exactly one write path** (`server/library/kv.go`). `update(fn)` holds a single `kvMu.Lock()` across read → mutate → write, because the store is one whole-file JSON blob: reading under `RLock` and writing under a separate `Lock` lost every concurrent set but the last (50 concurrent writers once kept 2 keys). Writes go through `x/atom` (tmp + rename), and a present-but-malformed store **refuses** the write rather than replacing thousands of keys with the one being set. Never add a second read-modify-write path. The parsed store is held **in memory** (`kvCache`): every read used to re-read and re-unmarshal all 650 KB / 7217 keys, and `MediaCodec` does two gets, so every `HLSMaster` parsed 1.3 MB of JSON before it could pick a codec. A `stat` per read (microseconds against a ~20 ms parse) keeps the old semantics exactly — a store replaced or corrupted behind our back is still noticed, so "refuse to write to a malformed store" survives the cache. `kvRead` hands out a shallow copy so callers can iterate after dropping the lock; `KVGetValue` reads one key under `RLock`.

**Pipeline ledger** (`server/library/pipeline.go` → `cache/pipeline.json`) records per-file, per-step state (`running`/`done`/`failed`). On boot `PipelineInit` resets surviving `running` entries to missing (interrupted → redo) and returns them so `main.go` can delete truncated `.tmp` output before the redo lands.

**`ProcessAll`** (`server/media/convert.go`) is the master background sweep, guarded by a CAS so it can't overlap. Order: `CleanAll` alone first (tree-mutating rename/move/flatten, so later phases walk a settled tree), then convert / scan+repair / thumbs+sprites→posters→anim / whisper / blurbs→embed / skips fan out concurrently. `posters` is chained after thumbs **and** sprites in the same goroutine: it reads the sprite sheet and overwrites the thumbnail, so running it alongside a thumbs pass writing the same path would stomp a chosen poster with a fixed-timestamp grab. Each phase has its own pool and skips busy files. `toMP4` also dispatches sprite/thumb/whisper per-file as each conversion lands, so a file gains its thumbnail while the next is still transcoding. Progress is a fixed-order phase state machine in `server/media/status.go`, polled by `ProcessStatus.svelte` via `/api/process/status`.

**Video streaming** has two paths:
1. Direct MP4 → HTTP 206 range requests (`server/media/player.go`)
2. HLS → `server/media/hls.go`. Codec is per-video via KV (`codec.go`), default h264:
   - **h264** (grandfathered library): adaptive ladder 144p–2160p plus a rung at the source's own (even) height when it falls between standard rungs (`srcRung` — a 1920x800 scope film otherwise topped out at 720p, a 1280x688 one at 480p; landscape only, borrows the next rung's caps, and `rungBandwidth` must advertise them: a missing BANDWIDTH read as a free rendition to ABR), 4s MPEG-TS segments transcoded on demand (hardware encoder when `encoders.go` finds one; `-enc_time_base:v demux` is load-bearing — without it the encoder re-times frames onto a grid starting at the cut and about half of all segments lost their last frame past `-t`, a hitch every few seconds on every h264 title, `TestE2E_SegmentBoundaryKeepsEveryFrame`), or keyframe-aligned `-c:v copy` passthrough when the source already matches a rung.
   - **av1** (new conversions): **demuxed CMAF** — hls.js can't demux fMP4, so video and audio ship as two *separate single-track* renditions. Video: one source-passthrough rung (`q=src`) `-c:v copy`'d into fMP4 (.m4s) + av01-only init. Audio: a separate AAC fMP4 rendition (`q=audio`) + mp4a-only init — always **stereo** (`-ac 2`; routing it through the surround-preserving `aacArgs` once made 176 files unplayable), `-c:a copy` when the source is already AAC at *exactly* 2ch (mono would copy into a track the master declares stereo) — joined via `#EXT-X-MEDIA:TYPE=AUDIO,GROUP-ID="aud"` / `AUDIO="aud"`. Both cut on the same keyframe-aligned bounds (CMAF sync). **`muxerBounds` replicates ffmpeg's hls muxer rule exactly** — split on the first keyframe where `pts - start_pts >= segDur * segmentsWritten`, which is an ABSOLUTE grid. The old rule was relative to the last cut; the two agree only while every GOP is >= `hlsSegDur`, and a 3s-GOP source produced a 6-segment playlist over 9 on-disk segments (wrong frames mid-file, playlist ending early). Don't "simplify" it back to a relative rule, and don't derive the playlist from ffmpeg's own `video.m3u8` — that needs the pass to finish before the playlist can be served, which reintroduces the startup stall the continuous-pass design exists to avoid. Each rendition is ONE continuous ffmpeg pass — per-segment `-ss`+copy re-snapped to the previous GOP and drifted the audio. No AV1 transcode ladder (no HW AV1 encoder → live transcode rebuffers). Marked-but-not-copy-eligible av1 falls back to the h264 ladder. **Never reintroduce a muxed AV1 segment** — it serves HTTP 200 but plays frozen in hls.js.

**AV1 capability gate.** `HLSMaster` resolves the codec per client, because an AV1-only master with no h264 alternate is a black screen on any device without hardware AV1 decode (iPhone 14 and older, pre-M3 iPads). The player probes with `MediaSource.isTypeSupported` (falling back to `canPlayType`) and sends `&av1=1` or `&av1=0` **on the master request only** — the master hands out URLs for whichever codec it resolved, so the choice propagates. Only the literal `"1"`/`"0"` are honoured; anything else falls through to a conservative User-Agent heuristic (iOS → h264; Chrome/Firefox/Edge → AV1; unknown or no UA → h264, since h264 always plays and a wrong AV1 is a black screen). The master is the only per-client artifact — it's `no-cache` + `Vary: User-Agent`, and everything it points at stays content-addressed and shared.

**`MediaCodec` keys on the BASENAME hash.** Codec marks are stamped at conversion time with the then-current rel path, but `CleanAll`/Organize move files between dirs afterwards — a dir-qualified key silently orphans the mark and the file falls back to the h264 live-transcode ladder. Basenames survive moves.

**HLS cache invalidation**: `hlsURLVer` (`server/media/hls.go`; its comment block is the changelog) cache-busts segment/init URLs, which are served immutable. Bump it on *any* change to the BYTES a segment or init carries — a rendition regenerated after an unbumped change makes one version serve two byte streams, pinned in browsers for a year. Bumping only busts clients/CDN — for pipeline changes to take effect server-side you must also `rm -rf ./cache/[0-9]*/`.

**Background conversion** (`server/media/convert.go`): non-MP4 formats auto-convert, **stored as AV1** (libsvtav1 preset 6; `-c:v copy` if already AV1), then marked `codec=av1` so HLS serves them by copy-passthrough. Bounded concurrency, `Nice` priority, writes to `<dst>.tmp` then atomic-renames. Source media capability (SAR/rotation/bit depth/color/channels) is carried in `srcInfo` and preserved — deanamorphize, rotation, 10-bit HDR copy, surround, portrait ladder. See `feedback_media_upgrade_principle`: preserve the best the source offers, downconvert only when a target can't.

**Compat mode** (`server/media/compat.go`): a per-download checkbox (Magnet/Downloads → `/api/compat`) that converts to H.264 + AAC (`compatCRF` 21, yuv420p, High) instead of AV1, so a TV can decode the file natively off `/video`. Decided at download time only — nothing re-encodes an existing title and no second copy is kept. Mark is `compat:<basename hash>`; `carryCompat` moves it onto the converted name, and clearing DELETES the key.

**TV app** (`server/tv/`, `src/tv/`, `server/media/tvplan.go`): a **second listener in the same process** on `TV_PORT` (4444) with a deliberately tiny route set — list, play, seek, subs, HLS, KV; no manage/organize/torrents. The same pages are also served at `/tv` and `/rc` on :4242 because the tailnet hostname only proxies there. `/` is the screen, `/rc` the phone remote (one bundle, routed on pathname). The **screen is a display, not a browser**: it subscribes to `/bus/events` (SSE — one-way, and `EventSource` reconnects on its own after the TV sleeps) and reports `/bus/state`; the phone owns navigation. State lives on the server so a reloaded remote or a second phone picks up exactly where things are. `TVPlan` decides direct-MP4 vs HLS ladder server-side: height > 1088 always forces the ladder **regardless of what the client claims** (a Fire TV stick's `canPlayType` says yes to 4K AV1 and then OOMs the whole page — not a catchable media error); 10-bit and AV1 go direct only when the screen claims `p10=1`/`av1=1`. The screen starts muted and reports `muted`/`full` back, because autoplay-with-sound and fullscreen both need a gesture the TV page never gets.

**`CleanAll` deletes on a junk DENYLIST, never an allowlist miss** (`server/library/clean.go`). It used to delete anything whose extension wasn't in a 12-entry video allowlist — which omitted `.m2ts`, `.mts`, `.vob` — and `jobs.OnDownloads` runs `ProcessAll` after every completed download, so a Blu-ray remux was destroyed about an hour after it landed. For the same reason nothing ever `RemoveAll`s a non-empty directory: `pruneEmpty` removes only genuinely empty ones. Release-group ad images (`www.YTS.MX.jpg`, `WWW.YIFY-TORRENTS.COM.jpg`) are on the denylist by name (`adRe`): once a film converted and flattened out, the ad was all that kept its release folder alive, and 17 such empty folders had piled up.

**Never use `filepath.Glob` on a user filename.** Go has no glob escaper, and `[` is a character class: `filepath.Glob("Movie [2020] 1080p.*")` returns `[]` with **`err == nil`** — a silent miss. About 7% of this library is `-[YTS.MX]`-style releases, and this bug independently shipped in four places (sidecar moves in organize, local-subtitle discovery, and both the delete and rename sidecar sweeps), stranding or failing to clean `.srt`/`.vtt` siblings. Use `os.ReadDir` on the parent plus a `strings.HasPrefix`/`HasSuffix` filter.

**Corrupt scan + repair**: `library.ScanCorrupt` builds a corrupt set; `media.RepairAll` tries progressively harder strategies, replacing in place and preserving the original as `<file>.corrupt.bak` (protected from the junk sweep by `keepSuffixes`).

**Clips** (`server/media/clip.go` + `src/player/clip.svelte`): mark in/out on the timeline, get a real file on the device. The output is **always H.264 + AAC in MP4 with `+faststart`** and an explicit `-pix_fmt yuv420p` — a clip exists to be shared, and AV1 (most of this library) and High10 are both refused by iOS Photos, Messages and WhatsApp. Never `-c copy`: that snaps the in-point to the previous keyframe, so a share clip starts seconds early on frozen frames. `-ss` ahead of `-i` is both the fast seek *and* the exact one when re-encoding. Long edge capped at 1920 with `setsar=1` (deanamorphize like `deanam` does for HLS); audio downmixed to 48 kHz stereo. Bounded: `ClipMaxSec` = 120s, `out <= in` rejected, both ends clamped to the probed duration, a 2-wide `jobs.Pool`, and an `FFRun.Timeout` proportional to the span (never `Nice` — this is interactive). Encoding is seconds, so it's **POST `/api/clip` → poll `/api/clip/status` → navigate to `/api/clip/file`**, not one held-open request: a navigation is the only way Safari saves an attachment, and it has to be its own request. The id is a content hash of `(rel, in, out)`, so a mashed button joins the in-flight job instead of queueing another, and `ClipFile` serves off the hex id alone — it must survive a restart that forgot the job map, because the client reaches it by navigation and a 404 would take the player's page down. Clips live in `cache/clips/`, evicted per request by age (6h) then oldest-first to `clipKeepMax`.

**Trickplay sprites** (`server/media/sprite.go`): one frame per 10s, 160px wide, 10 columns → `images/{key}.sprite.jpg` + `.sprite.json` manifest served by `/api/sprite/:key`. Key = `library.Hash(basename)`, same as thumbnails. Idempotent.

**Poster selection** (`server/media/poster.go`): the thumbnail used to be one ffmpeg grab at `duration/2 ± 5s`, which landed on a black frame, a fade or the credits for **5.7% of the live library** (measured over all 1958 sheets). The candidates are already on disk — the sprite sheet is one frame per 10s — so the `posters` phase decodes that sheet instead of running any new ffmpeg pass and scores every tile classically: mean/stddev of luma, Hasler-Süsstrunk colourfulness, mean absolute luma gradient. Hard-rejects near-black, near-white, near-uniform and detail-free frames; trims the first and last 5% (logos, credits). That alone takes the reject rate to 0.1% and the p10 score from 0.298 to 0.772. The top 6 well-separated survivors then go to a vision model (`POSTER_VISION_MODEL`, one `/api/generate` with an `images` array) which answers `{"pick": N}` — **strictly optional**: `visionReady` probes and loads once per sweep, calls are serialised through a 1-wide gate (ollama runs one request per model, so parallel calls only queue and then all time out together), and three consecutive failures disable the stage for the sweep. Any failure ships the classical winner. There is no cheap classical text detector — luma-bin dominance, colour coverage and edge-band skew were all measured and none separate a title card from a scene — which is exactly the judgement the vision stage is there to make. The winner is written with one full-res `-ss` grab at its timestamp (the 160px crop is the fallback), atomically via `x/atom`. Mark is `poster:<hash>` on the **basename** hash like `codec:`/`skip:`; presence = chosen. `media.RepickPoster(abs)` / `media.PosterRedo` re-run one file.

**Skip detection** (`server/media/skip.go`): episodes in a folder share intro/outro audio, so head/tail PCM fingerprints are cross-matched against a sibling. Needs ≥2 episodes; matches must run ≥15s and ≤300s. Persisted as `skip:<hash>` in KV, keyed on the **basename** like `codec:` (a dir-qualified key orphans the moment `CleanAll`/Organize moves the file, which silently re-ran PCM fingerprinting on already-scanned episodes); presence = scanned. The player turns these into skip buttons and does a seamless in-place next-episode swap (keeps Chrome's autoplay allowance). The thresholds are empirically tuned — don't "simplify" them.

**Subtitle waterfall** (`server/media/subs.go` + `src/player/subs.ts`): local VTT → SRT → embedded extraction → OpenSubtitles (hash, then title) → Subdl (title) → Whisper. `SubResult.Provider` distinguishes "os" from "subdl"; `GetSubs` branches on it. `subnormalize.go` defensively strips BOM/leading junk at every parse site — Windows-saved SRTs otherwise fail with `strconv.Atoi: parsing "<BOM>1"`.

**Subtitle auto-sync** (`server/media/subsync.go`): a downloaded subtitle is fitted to the film as `t_video = scale·t_sub + offset` by correlating cue presence against voice-band (300–3000 Hz) loudness in 10ms frames, cached per video in `cache/speech/<hash>.bin` behind a size+mtime stamp. The speech signal has its 4s local mean subtracted — without it, drift in dialogue density buried the true peak (z≈4; a Korean film never aligned); with it true fits score z 14–37 while a deliberately wrong subtitle never beats 4.8. The sidecar is **never rewritten**: the fit lives in KV as `subsync:<basename hash>` (stamped with the sub's size, carried by `MoveSidecars`) and `SubsSend` applies it at serve time with `Cache-Control: no-cache`, so undo is `DELETE /api/subs/sync`. It runs automatically after an OpenSubtitles/Subdl download and on demand from the subtitle menu, never niced (the throttled IO tier made a 25-minute episode take a minute, and a viewer is always waiting), and applies only when `verdict()`'s gate clears: peak ≥ 8σ, lead over the runner-up ≥ 4σ, gain over identity ≥ 2σ, ≥ 60 cues; frame rate 1 wins unless another rate beats it by 3σ, because over a short file a 0.1% stretch and a small offset are interchangeable. One linear transform per file — piecewise cuts aren't handled.

**Whisper** (`server/jobs/whisper.go` + `tools/stream_whisper.py`): async transcription via a faster-whisper Python subprocess, SSE-streamed to the frontend. Python is a hardcoded conda `global` env path. `whisper_auto.go` backfills after conversion, throttled to ONE concurrent run, skipped when any English sidecar (or a prior `.whisper.vtt`) exists. Non-English audio is post-translated through ollama (`OLLAMA_MODEL`), with a glossary of proper nouns lifted from a sibling episode's English sidecar (`glossary.go`) — a model cannot infer a name it was never told. When translation fails the sidecar ships in the source language; `retranslate.go` (`POST /api/subs/retranslate`) repairs those by substituting text LINES in place, never re-parsing cues (that would drop `[DOOR SLAMS]`/`♪` cues) and never redoing ASR.

**Blurbs** (`server/jobs/blurb.go`): spoiler-free two-sentence descriptions, generated from the `.vtt` sidecar a title already has — there is no metadata provider. `parseCues` is a standalone timing-driven VTT parser (headers/NOTE blocks/sound effects fall out; BOM stripped like `subnormalize.go`), and `opening` hands the model **only the first 15% of the runtime** — a hard front-of-file slice, because a prompt can be ignored and a slice cannot. Runtime comes from the last cue's end, not ffprobe: it can only under-estimate, which moves the cut earlier. Under 400 chars of opening dialogue, the title is skipped rather than described from its filename. Cached as `blurb:<hash>` keyed on the **basename** like `codec:`/`skip:`; presence (including `""`, meaning "the model had nothing to say") means done. The sweep is a `blurbs` phase in `ProcessAll` on a 1-wide pool, and probes ollama once up front — a sleeping tailnet host would otherwise cost one chat timeout per file. Served whole at `/api/blurbs` as `{hash: text}`, joined client-side against the `key` the video list already carries, so the list payload stays small.

**Search** (`server/jobs/find.go`, `embed.go` → `/api/find?q=`): plain-language library search ("korean crime" → The Roundup), shown under Home's substring results as "Close in meaning". One vector per TITLE: an episode is whatever precedes its `SxxEyy` marker (so a show unifies across differently named season folders), and in a folder of 3+ files a file named after the folder joins it (bare-numbered anime). Each title is embedded from its name plus its first 3 distinct blurbs — a bare name measured near-random — via an `embed` phase chained after `blurbs` in `ProcessAll`. Vectors live in `cache/embed.bin` (raw float32, NOT the KV store), stamped with the exact input text and model, so a late blurb re-embeds and a model swap drops the store. Queries use the model's instruct format (raw queries let blurb-less titles top every list) and keep hits ≥ 0.30 and within 0.12 of the best — measured with `qwen3-embedding:4b`; re-measure for any other embedder. Any failure answers `[]`, never an error. (This replaced a recommendations row that nobody used — and that had been 404ing for a month on a vanished `nomic-embed-text`.)

**Reclaim space** (`src/library/reclaim.ts` → `Reclaim.svelte` in Manage): finished titles last watched 30+ days ago, biggest first; a whole folder is offered only when every file actually in it (per Manage's listing, never history's name-normalised join) qualifies. The watch log never records the end of a finished title — reaching the player's `END_CUTOFF_S`/10% line CLEARS the `watched:` record and a clear isn't logged — so "finished" means within that line + 30s, judged against the live `resume` position `/api/history` now carries, so a rewatch or a title parked on its credits isn't mistaken for done. Delete is per row, two-tap, never bulk.

**Episode gaps** (`series.ts` `gaps`/`holes`, shown in SeriesStrip/ShowRow/Tonight) flag only INTERIOR holes. The user deletes watched episodes, so a missing head is history, and a missing tail counts only when the folder name declares a range (`Bleach 140-167`). Anything with a watch record (from `/api/history`, matched by parsed title + season + episode, never by path) is not a gap; history is fetched only when some row has a candidate, and gaps stay hidden until it arrives. Strips and Tonight use `order()` (episode order, not filename order — `S01E02v2` sorted after E12 and Tonight skipped it), and a missing next episode makes Tonight say so with a "Search torrents" action instead of skipping ahead.

**History** (`server/library/history.go` → `/api/history` → `/history`): one row per FILE, not per torrent. The saved `.torrent` files (aria2 `--bt-save-metadata`; the `.torrent`'s mtime *is* the download date) are only the discovery mechanism — `CleanAll` moves finished ones into a hidden `<root>/.torrents/` (a same-drive rename keeps the mtime; never delete them, and `walkRoots` reads that dot-dir on purpose), while a download aria2 still holds keeps its `<dir>/<infohash>.torrent` in place because `refreshTorrentPaths` marks it busy for `--bt-load-saved-metadata` — each file is then joined across the watch log, KV marks, pipeline ledger, HLS cache and disk. A store that doesn't know a field leaves it zero and the UI prints a dash. Has its own dependency-free bencode decoder that must error, never panic, on a corrupt `.torrent`.

**Torrents & downloads**: `/api/search` fans out to TPB/Knaben/torrents-csv/Nyaa (`search.go` + `providers.go`), dedupes by infohash, sorts by seeders. aria2 needs persistent DHT at `./cache/aria2.dht.dat` (not root-owned `~/.aria2/`), fixed listen ports, and global tracker fallback — "stuck at metadatafetch" is almost always zero peer connections. Flag changes silently don't apply if a stale aria2c is still holding :6800; `pkill aria2c`. `ytdlp.go` covers non-torrent URLs.

**LLM organize** (`server/jobs/organize.go`) groups only **series and franchises** — a standalone film stays where it is (there are no decade/language buckets any more; the old decade folders were merged into one `Movies` per root). It runs on **saturn** (`saturn.go`), through `/v1/chat/completions` on whatever saturn's chat lane resolves to (`GET /agent/model`, resolved once per plan; `ORGANIZE_MODEL` overrides). Never trial other saturn models. Three things make it fast and right, all measured: (1) **films are looked up first** via saturn's `/search/web` (no LLM, ~1.5s, **3 wide** — 8 wide tripped the provider's rate limit and lost 24 of 34 lookups), because franchise membership is a fact the model must be told: without it *The Outlaws* (2017) was never joined to The Roundup. (2) The model reasons **~1.5k chars per file whatever the prompt says**, so one whole-library call took 70–120s and the gateway cuts at 120s; files go in **batches of 4, all fired at once**, each seeing the whole list as context but deciding only its own. (3) Every batch is sent **twice** and the answers unioned — a reply's failure mode is omission (four obvious episodes came back `{"moves": []}` one run and fully placed the next), never a wrong index. 42 files: ~70s, was 4.5min with a failed run. The default model is a hosted DeepSeek that ignores `response_format`'s schema, so the prompt spells the JSON out; `validMoves` bounds indexes, drops single-file folders, and snaps a copied-back listing count (`"Foo (2)"`) to the existing `Foo`. The model only ever sees an indexed list and answers `{index → folder}` — filenames never round-trip, so a hallucination can't corrupt a move. Plan is a background job (POST `/plan`, poll `/status`); nothing touches disk until the user posts an approved subset to `/apply`.

**Stats** (`server/library/stats.go`): `cache/stats.jsonl` is appended by `statsTee`, called from `KVSet` for any payload that smells like a watch record — no separate frontend POST. Watch pings are attributed to a device via Tailscale identity (`jobs/tailscale.go`, resolution ladder deliberately excludes tags: a tag is a permission category shared by many devices). `StatsSummaryHandler` aggregates it, but is currently **not registered in main.go** — the /stats frontend page is gone.

**Reactive state**: `PlayerState` in `src/core/events.svelte.ts` is the single source of truth for player chrome. Runes need a `.svelte.ts` extension — `$state` in a plain `.ts` builds fine but ReferenceErrors at runtime.

## External Dependencies

- **ffmpeg / ffprobe** — required. `encoders.go` probes `ffmpeg -encoders` once and picks hardware paths (VideoToolbox / NVENC / QSV / AMF) when present. No zscale in this build, so there's no correct HDR tonemap; SVT-AV1 drops `color_trc`/`primaries` and only the bt2020 matrix survives.
- **aria2c** — optional, JSON-RPC on localhost:6800
- **yt-dlp** — optional, non-torrent URL downloads
- **faster-whisper** — optional, Python package in conda `global` env
- **ollama** — optional, subtitle translation, blurbs, poster selection, anim detection, search embeddings
- **saturn** — optional LLM gateway for organize (`SATURN_HOST`)
- **tailscale** — optional, `tailscale status --json` for stats attribution

## Environment Variables (`.env`)

- `OPENSUBTITLES_API_KEY`, `OPENSUBTITLES_USER`, `OPENSUBTITLES_PASS`
- `SUBDL_API_KEY` — optional fallback; unset skips that waterfall step silently
- `PORT`, `TV_PORT` — defaults `4242`, `4444`
- `OLLAMA_HOST`, `OLLAMA_MODEL` — code defaults `http://100.117.92.56:11434`, `aya-expanse:8b` (rejected on quality; `.env` sets `gemma4:12b-it-q8_0`)
- `EMBED_MODEL` — search embeddings, default `qwen3-embedding:4b-q8_0` (the old `nomic-embed-text` default vanished from the host and 404'd for a month)
- `SATURN_HOST`, `ORGANIZE_MODEL` — organize backend; unset `ORGANIZE_MODEL` means saturn's current default chat model
- `POSTER_VISION_MODEL` — vision model for poster selection and `anim`, `.env` sets `gemma4:12b-it-q8_0` (the code default is an nvfp4 build, which does not run on this llama.cpp host). Shares `OLLAMA_HOST`. **Verify the configured id is actually on the host**: `qwen3.8:27b-q8_0` vanished from it and the only signal was one boot line, while posters, blurbs and subtitle translation all silently no-opped. Gemma4 *does* accept an `images` array now (measured: it picked a tile out of a real 10x15 sprite sheet) — the older note that the Gemma builds reject `images` no longer holds. `POSTER_VISION=0` turns the stage off without touching the network — the classical pick then ships unchanged.

`WHISPER_MODEL` still appears in `.env` but is no longer read — the whisper model comes from the `?model=` query param (default `base`).
